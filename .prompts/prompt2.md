 Для barcode-маркерів (THREEx.ArMarkerControls) бібліотека ARToolKit розраховує повну матрицю орієнтації 6-DOF, яка жорстко прив'язана до площини картки: коли ви повертаєте маркер    
  у руках, 3D-об'єкт природно повертається разом із ним.

  Для ArUco-маркерів зображення виглядає зафіксованим або не повертається разом із карткою через помилки в розрахунку орієнтації у файлі aruco.js:90-123:
  ──────
  ### Причини проблеми в коді:

  1. Інвертоване обертання (транспонування матриці):
      • У рядках aruco.js:97-102:
        rotMatrix.set(
            rotation[0][0], rotation[1][0], rotation[2][0], 0,  // транспоновано
            rotation[0][1], rotation[1][1], rotation[2][1], 0,
            rotation[0][2], rotation[1][2], rotation[2][2], 0,
            0, 0, 0, 1
        );

      • Алгоритм POSIT (POS.Posit) повертає матрицю у звичайному форматі за рядками. Транспонування ортогональної матриці математично інвертує обертання (Rᵀ = R⁻¹), через що кут       
      повороту маркера в площині спотворюється або нівелюється.
  2. Конфлікт осей з ARToolKit:
      • У рядках aruco.js:111-119 застосовується трансформація _artoolkitProjectionAxisTransformMatrix:
        var tmpMatrix = new THREE.Matrix4().copy(_this.context._artoolkitProjectionAxisTransformMatrix);
        tmpMatrix.multiply(rotMatrix);

      • Система координат POSIT відрізняється від внутрішніх осей ARToolKit. Це множення розвертає нормаль маркера вглиб екрана (вздовж -Z), через що грань з текстурою дивиться у      
      зворотний бік.
  3. Текстурування BoxGeometry:
      • У файлі config.json:31-37 використовується тривимірна коробка BoxGeometry, де текстура накладається на всі 6 граней. Через розвертання нормалі користувач бачить бічну або      
      протилежну грань, яка візуально здається нерухомою відносно повороту картки.

  ──────
  ### Як це виправити:

  Ми можемо оновити функцію updateObjectPose у файлі aruco.js:90-123:

  1. Не транспонувати матрицю POSIT, зберігши правильний прямий порядок елементів.
  2. Застосувати коректну корекцію осі нахилу відповідно до офіційного прикладу js-aruco2 (makeRotationX(-Math.PI / 2)).
  3. Забезпечити точне обертання 3D-зображення вслід за поворотом маркера, як це працює для barcode.

   ### Чому barcode-маркери працюють правильно:
  Для barcode-маркерів (THREEx.ArMarkerControls):

  1. Движок ARToolKit вираховує повну матрицю просторової позиції та орієнтації маркера (modelViewMatrix).
  2. Ця матриця безпосередньо розкладається на markerRoot.position та markerRoot.quaternion.
  3. 3D-об'єкт є дочірнім елементом markerRoot, тому він жорстко прив'язаний до площини картки: коли ви повертаєте фізичну картку в руках, 3D-модель природно повертається синхронно    
  з нею.
  ──────
  ### Чому для ArUco-маркерів зображення не повертається:

  У класі ArucoMarkerControls у файлі aruco.js:90-151 розрахунок орієнтації порушує цю прив'язку:

  1. Матриця обертання інвертована через транспонування:
      • У рядках 98–101 матриця зчитується як rotation[0][0], rotation[1][0], rotation[2][0]... через помилкове припущення, що POSIT повертає стовпчиковий порядок. POSIT насправді     
      вже повертає правильні рядки. Транспонування інвертує обертання (Rᵀ = R⁻¹), через що обертання маркера в площині блокується або розвертається у зворотний бік.
  2. Конфлікт матриці осей ARToolKit з POSIT:
      • У рядках 113–118 застосовується матриця _artoolkitProjectionAxisTransformMatrix. Вона створена суто під внутрішню систему координат ARToolKit. Застосування її до результатів   
      POSIT перевертає нормаль маркера вглиб екрана (вздовж -Z), що «відриває» площину об'єкта від площини картки.

  ──────
  ### Як це вирішити:
  Ми можемо оновити функцію updateObjectPose у файлі aruco.js:90-151:

  1. Використати прямий порядок рядків матриці з POS.Posit без інвертування.
  2. Застосувати стандартну корекцію Three.js без спотворюючого множення на внутрішню матрицю ARToolKit.
  3. Забезпечити жорстку синхронізацію 3D-зображення з площиною маркера, щоб воно оберталося точно так само, як і для barcode-маркерів.

  ### Що було змінено в ArucoMarkerControls:

  1. Виправлено порядок матриці (прибрано інвертоване транспонування):
      • У функції updateObjectPose матриця rotMatrix тепер заповнюється у прямому порядку (row-major) безпосередньо з POS.Posit:
        rotMatrix.set(
            rotation[0][0], rotation[0][1], rotation[0][2], 0,
            rotation[1][0], rotation[1][1], rotation[1][2], 0,
            rotation[2][0], rotation[2][1], rotation[2][2], 0,
            0, 0, 0, 1
        );

  2. Застосовано канонічну корекцію орієнтації:
      • Додано точну кутову корекцію осі (rotationX(-Math.PI / 2)), яка правильно вирівнює площину маркера зі сценою Three.js.
  3. Прибрано конфліктне множення осей та штучні зміщення:
      • Вилучено множення на _artoolkitProjectionAxisTransformMatrix та статичні зміщення (positionOffsetX/positionOffsetZ), які раніше зміщували центр і розвертали нормаль у
      протилежний бік.
  4. Індивідуальне калібрування розміру маркерів:
      • Кожен екземпляр контролера тепер ініціалізує власний POS.Posit з точним значенням modelSize з файлу config.json (15 мм, 30 мм тощо), що гарантує точне позиціонування по        
      глибині.


  Тепер під час повороту ArUco-картки в руках 3D-зображення обертатиметься синхронно разом із маркером, точно так само, як і для barcode-маркерів.
